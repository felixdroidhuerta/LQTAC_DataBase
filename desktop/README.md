# LQTAC Data Base · Desktop 0.1

Primera aplicación Electron independiente dentro del repositorio DBeaver. El código Java original permanece disponible como base de la futura integración JDBC. Los adaptadores nativos de Electron permiten conectar con PostgreSQL (pg), MySQL/MariaDB (mysql2), SQL Server (Tedious), Oracle Thin (node-oracledb), ClickHouse y MongoDB, además de SQLite local mediante sql.js. Todavía no ejecuta el núcleo DBeaver.

## Versión portable para Windows

`npm run build:portable` genera `LQTAC-DataBase-0.1.6-win-x64-portable.zip` y su carpeta extraída junto a la carpeta del proyecto, fuera de este. En este equipo se guardan directamente en `Documents`, igual que las versiones portables de LQTAC Studio. Incluye Electron y las dependencias de producción. Extrae el ZIP completo y abre `LQTAC Data Base.exe`; no requiere instalar Node.js. El empaquetado sigue la distribución manual de Electron: https://www.electronjs.org/docs/latest/tutorial/application-distribution.

La presencia de `portable.json` activa el almacenamiento de conexiones, borradores, preferencias, caché y copias de seguridad en `Data` junto al ejecutable. Cierra el programa antes de mover la carpeta completa. El paquete sale limpio, sin copiar conexiones ni datos personales del entorno de desarrollo. Los archivos SQL guardados fuera de esa carpeta y la configuración de VPN del sistema deben trasladarse o configurarse aparte. Para actualizar, extrae una versión nueva en otra carpeta y copia allí tu `Data`, con ambas aplicaciones cerradas. El generador rechaza sobrescribir una carpeta existente para proteger sus datos.

`node desktop/test/portable-smoke.cjs`, desde la raíz del repositorio y sobre un paquete recién generado, abre el ejecutable real, comprueba el logo, ejecuta SQLite y verifica la persistencia de preferencias tras reiniciar; elimina únicamente su Data de prueba. No contacta servidores externos.

## Arranque de desarrollo

Con Node.js y npm instalados, desde `desktop`:

```powershell
npm ci
npm start
```

En Windows, después de instalar las dependencias, también puedes abrir `Abrir-LQTAC.cmd` desde la raíz del proyecto con doble clic. El lanzador usa directamente Electron, sin necesitar npm en el PATH.

Pruebas del adaptador: `npm test`.

## Funciones disponibles

- Edición de registros en Resultados: ejecuta `SELECT * FROM esquema.tabla` y activa **Editar datos**. Doble clic, F2 o escribir sobre una celda abre el editor; Enter confirma el valor pendiente, Escape lo cancela y Tab pasa al siguiente campo editable. **Aplicar cambios** guarda las filas; **Descartar** recupera los valores anteriores. NULL se asigna con su botón y es distinto del texto `NULL` o una cadena vacía. Los cambios pendientes se resaltan y se pide descartarlos antes de cambiar de consulta o cerrar su resultado.
- El pequeño tirador de la celda seleccionada copia su valor al arrastrarlo por otras filas de esa columna. El doble clic en el tirador rellena esa columna en todas las filas visibles del resultado. El orden y el filtro utilizan los valores originales mientras hay cambios pendientes, para mantener estable el bloque que se rellena. No se modifican filas fuera de la cuadrícula cargada; se mantiene el límite de resultados.
- Disponible para MySQL/MariaDB, PostgreSQL y SQLite con una tabla directa y su clave primaria. Vistas, joins, agregados y tablas sin clave se mantienen en lectura. Las claves, columnas generadas y tipos complejos/binarios son de solo lectura. Los otros motores conservan la consulta y exportación de resultados. Cada edición se vincula al resultado, sesión y tabla originales; se verifica la estructura y se comparan las claves y los valores anteriores de las celdas editadas para detectar conflictos.
- Los cambios se aplican **fila a fila**: si falla una, se detiene el proceso y se conservan pendientes esa fila y las restantes. No hay COMMIT ni ROLLBACK implícitos sobre transacciones abiertas. SQLite modifica la copia en memoria y requiere Guardar copia para persistir un archivo. Los valores se vinculan con parámetros en SQLite/PostgreSQL y se codifican como literales hexadecimales UTF-8 en MySQL, sin depender del modo de escape. Una interrupción de escritura exige volver a consultar antes de repetirla. `npm run test:data-edit` verifica edición, arrastre nativo, autorrelleno, aplicación, descarte, orden y filtros contra SQLite real en memoria; las pruebas de modelo cubren conflictos, sesiones, estructura y literales.

- Al vencer el tiempo máximo se devuelve inmediatamente **Agotado tiempo máximo de consulta**, se detienen las sentencias restantes y se libera la interfaz. Detener y el timeout solicitan la misma cancelación nativa en segundo plano. No se espera a la confirmación para mostrar el resultado del lanzamiento ni se fuerza una desconexión. Si el servidor tarda o no responde, solo esa sesión queda reservada, sin encolar consultas ni lecturas de metadatos en ella; otras conexiones siguen disponibles. Detener permite reintentar, y una notificación libera la reserva cuando terminan tanto la respuesta original como los comandos de cancelación. No se reintenta SQL ni se hace ROLLBACK automáticamente.

- Botón rojo ■ en las herramientas SQL: detiene la sentencia activa y las restantes del script. También al agotarse el tiempo se intenta cancelar únicamente la consulta, conservando la sesión. MySQL/MariaDB usan KILL QUERY desde una conexión auxiliar con el mismo usuario; PostgreSQL, pg_cancel_backend; SQL Server, ATTENTION; Oracle, break; ClickHouse, KILL QUERY por query_id; MongoDB, búsqueda de la operación propia por un identificador y killOp. Se muestra el resultado de la interrupción sin esperar al servidor, y se drenan la respuesta y la cancelación en segundo plano antes de reutilizar esa conexión, sin reintentos ni ROLLBACK automáticos. El timeout y Detener usan la misma ruta y no cierran automáticamente la sesión. Los permisos del servidor pueden limitar estas operaciones; después de cancelar dentro de una transacción puede ser necesario ejecutar ROLLBACK. SQLite en memoria no admite detener una consulta ya iniciada en esta versión y su botón permanece desactivado.
- Herramientas agrupadas y separadas por `|`: archivos SQL, formato, ejecución y relaciones; en Resultados, copiar, exportar y filas visibles. El botón Detener permanece operativo mientras los demás comandos SQL están ocupados, se desactiva al finalizar y queda ligado al identificador de su lanzamiento para no cancelar consultas posteriores.

- Configuración (⚙ en la barra Workspace): tiempo máximo por sentencia enviada a un servidor, entre 1 y 86400 segundos, con 30 segundos como valor inicial. Se guarda en `settings.json` dentro de los datos de la aplicación (en el portable, `Data`) y se aplica al siguiente lanzamiento sin reconectar. Cada sentencia de un script recibe su propio plazo; cambiar el ajuste no altera el script que ya está en curso. Combina los límites del controlador con un plazo para recibir la respuesta completa. Si vence ese plazo, muestra «Agotado tiempo máximo de consulta», solicita la misma cancelación que Detener y detiene el script sin esperar al servidor, sin reintentos ni desconexión forzada. No cambia el tiempo para establecer una conexión ni el de lectura de metadatos. SQLite local en memoria no utiliza este límite. Los límites y permisos impuestos por el servidor siguen teniendo efecto.
- En el editor SQL y los editores de triggers, vistas y rutinas, Tab inserta una tabulación (ancho visual de cuatro espacios), y Mayús+Tab quita un nivel de sangría. Con varias líneas seleccionadas se aplica al bloque, conservando selección, foco y deshacer/rehacer nativos. Tab siempre indenta, incluso con sugerencias abiertas; Enter acepta el autocompletado. En los formularios y demás controles, Tab mantiene la navegación habitual. `npm run test:settings` comprueba la configuración, el teclado nativo y el vencimiento de una consulta MySQL contra un simulador local, sin contactar servidores reales.

- Cada pestaña del marco Resultados incluye ×, también cuando solo queda una. Se puede cerrar además con el botón central o Supr sobre la pestaña enfocada. Cerrar una salida conserva la consulta SQL y las demás salidas; si era la activa, se selecciona una vecina. Si se cierran todas, se desactivan filtros y exportación hasta ejecutar de nuevo. La exportación conserva el índice original del resultado para no confundir tablas tras un cierre.

- Ejecutar / Ctrl+Enter lanza la sentencia SQL donde está el cursor, aunque ocupe varias líneas. Si hay una selección explícita, ejecuta solo ese texto; Ctrl+Mayús+Enter sigue exigiendo selección. El punto y coma separa las sentencias fuera de cadenas, identificadores, comentarios y bloques. Se respetan cuerpos PostgreSQL dollar-quoted, bloques BEGIN/END, delimitadores MySQL/MariaDB declarados con DELIMITER y separadores Oracle `/` en su propia línea. Un borrador incompleto posterior no impide ejecutar una sentencia anterior completa desde el cursor.
- Botón ⚡ en las herramientas SQL, o F5 en el editor: ejecuta todo el documento en orden sobre la misma sesión, restaurando su base/esquema antes del lanzamiento. Hay pestañas de resultados para cada salida, incluidas confirmaciones sin filas y errores; los CALL que devuelven varias tablas generan varias pestañas. Cada tabla conserva sus filtros/orden y puede copiarse o exportarse independientemente. En Salidas se actualiza cada sentencia al empezar y terminar, con su hora, duración y filas.
- El lanzamiento se detiene en el primer error y conserva los resultados anteriores. No abre una transacción ni revierte escrituras ya realizadas: las transacciones son las que el usuario escriba y las que admita el motor. No se reintenta automáticamente. SQL Server conserva los lotes separados por GO, para mantener variables T-SQL dentro de cada lote; GO con contador de repeticiones se rechaza. MongoDB sigue aceptando un único comando JSON por documento. Cada lanzamiento admite hasta 100 sentencias/lotes y retiene como máximo 200 resultados o unos 32 MB en total; el límite de filas de la UI se aplica a cada tabla. Si se supera el tamaño de una respuesta, la sentencia puede haberse ejecutado y no debe repetirse sin comprobar su estado.
- `npm run test:statements` verifica cursor sobre SQL multilínea, selección, rayo con varias salidas, pestañas/exportación y parada ante error sin ejecutar escrituras posteriores. Las pruebas de modelo cubren separadores dentro de literales/comentarios, rutinas, DELIMITER, dollar-quotes, PL/SQL y lotes GO.

- Resultados y Salidas: clic para seleccionar fila y celda con resaltados distintos, botón ⧉ o Ctrl+C para copiar el contenido completo, Ctrl+Mayús+C para copiar la fila en TSV y botón derecho con Copiar celda, Copiar fila y Ver contenido completo. Doble clic o Enter abre el valor en un visor de texto seleccionable; no lo ejecuta. Las flechas desplazan la celda activa. Se conserva la selección de la fila original al ordenar, y copiar usa el valor completo aunque la celda esté recortada visualmente. Las salidas conservan SQL y mensajes completos; el historial está limitado a 200 entradas y aproximadamente 8 millones de caracteres acumulados de SQL/mensajes, retirando las más antiguas. Copiar no altera datos ni ejecuta SQL.
- Herramientas SQL: Abrir (Ctrl+O), Guardar (Ctrl+S) y Guardar como (Ctrl+Mayús+S). Abrir crea una pestaña con el archivo, sin ejecutar su contenido; una marca • indica cambios no guardados. Los borradores siguen siendo locales y guardar un archivo es una acción explícita. Se admite UTF-8 y UTF-16 con BOM, conservando la codificación al guardar sobre el archivo original; un archivo nuevo usa UTF-8. Se valida un máximo de un millón de caracteres y 4 MB al abrir. Los destinos autorizados por los diálogos se recuerdan mediante referencias opacas en `sql-file-references.json`, sin permitir que el renderer elija rutas arbitrarias. Esto permite Ctrl+S después de reiniciar. Las escrituras se preparan en un temporal antes de reemplazar el destino.
- Cada consulta conserva su perfil, base/esquema y pestaña activa al cerrar. Antes de ejecutar, la sesión correcta se activa y el backend restaura ese contexto dentro de la misma operación exclusiva. Las consultas recuperadas no se redirigen a otra conexión. Si su perfil está desconectado, Ejecutar abre su autenticación y recupera la misma consulta; después hay que pulsar Ejecutar de nuevo, sin reenvío automático de sentencias. Cambiar la base desde la estrella o el selector del editor cambia la base asociada a esa consulta. Si se cambia la configuración del perfil, se adopta el contexto de la nueva conexión en lugar de conservar una base de otro servidor. En SQL Server se restaura también la base física; en PostgreSQL/Oracle se distingue la base/servicio del esquema. Si un borrador antiguo no guardaba su base y el perfil la tiene vacía, hay que elegirla una vez en el selector: no se adivina otra base por nombres de tablas.
- `npm run test:workflow` valida selección/copia íntegra de SQL largo en resultados y salidas, menú y visor, abrir/guardar/guardar como y recuperar una pestaña tras recarga con su sesión cerrada. Comprueba reconexión al mismo perfil y base sin ejecución automática. El portapapeles y los diálogos usan dobles en el test para no alterar el portapapeles del usuario. Las pruebas de modelo recrean el almacén de archivos para verificar referencias tras reinicio, UTF-8/UTF-16 y selección de contexto con el driver MySQL real contra un simulador local.

- Resultados ordenables por cualquier cabecera: cada clic alterna ascendente, descendente y el orden original. Los números se comparan numéricamente, incluidos enteros grandes recibidos como texto, sin convertirlos a Number ni perder precisión; los NULL se mantienen al final. El orden es estable para valores iguales. Las cabeceras funcionan también con teclado e indican su estado.
- Antes de las herramientas de resultados hay un selector de campo (o Todos los campos) y una búsqueda por contenido, sin distinguir mayúsculas ni acentos. Son filtros locales de las filas ya recibidas: no vuelven a ejecutar SQL, no recorren datos que quedaron fuera del límite y no cambian el servidor. Vaciar el texto recupera las filas; se informa cuántas coinciden. Los nombres de columna repetidos se identifican por posición. Si hay varios resultados, el selector permite ver, ordenar, filtrar y exportar uno cada vez, conservando filtros independientes mientras se mantiene esa ejecución. Una consulta nueva limpia esos filtros.
- CSV/XLSX exportan las filas filtradas en el orden visible, con las cabeceras originales. El backend valida índices de filas sobre su copia del resultado: no acepta celdas inventadas desde la interfaz. Con cero coincidencias se exportan las cabeceras. `npm run test:results` verifica orden, filtros, coincidencias vacías, exportación filtrada/ordenada, cambio de resultado y modo oscuro; las pruebas de modelo comprueban precisión numérica, estabilidad, NULL, acentos y validación de índices.

- Autocompletado de columnas SQL según las tablas/vistas referenciadas y el esquema elegido, con alias (`SELECT p.no FROM proyectos p`), JOIN y nombres cualificados. Las sugerencias indican tabla/alias y tipo. Enter inserta, flechas seleccionan y Ctrl+Espacio fuerza la lectura de metadatos. Solo se consultan hasta ocho tablas de la sentencia actual; hay una espera breve al escribir y caché de un minuto, invalidada al actualizar el explorador, ejecutar o cambiar sesión. No se leen filas de usuario para predecir columnas. Literales/comentarios no generan sugerencias. Es un analizador ligero: no infiere columnas de CTE, resultados calculados, tablas derivadas ni documentos MongoDB sin esquema fijo.
- Lápiz ✎ junto a vistas, procedimientos y funciones: abre su definición completa con colores, Recargar, Revisar SQL y Aplicar. Revisar no modifica el servidor; una modificación del texto invalida la revisión. La revisión dura diez minutos, queda vinculada a sesión/objeto/versión y se vuelve a comprobar antes de aplicar. Se conserva el nombre y esquema. Las definiciones originales se copian en `object-backups/*.json` dentro de los datos de la aplicación. Los cambios remotos usan una sesión independiente para no confirmar ni alterar las transacciones abiertas en el editor SQL.
- MySQL/MariaDB: vistas mediante CREATE OR REPLACE conservando DEFINER, modo SQL y collation; procedimientos/funciones mediante DROP+CREATE. Ese cambio de cuerpo no es atómico: la revisión muestra el intervalo sin rutina y los permisos afectados. Se exige poder conservar el DEFINER. Si se pueden leer los permisos específicos de `mysql.procs_priv`, se incluyen en la revisión y se restauran; si no son visibles, se avisa para revisarlos manualmente. Un cambio concurrente en los permisos legibles invalida la aplicación. Si CREATE falla con conexión sana, se intenta restaurar la definición y permisos leídos; si se pierde la red, no se reintenta a ciegas. La copia JSON incluye la definición original y los GRANT disponibles. No hay garantía de restauración ante fallos de red/permisos ni bloqueo exclusivo frente a otros administradores.
- PostgreSQL: vistas y rutinas mediante CREATE OR REPLACE; se conserva el contexto search_path para leer y compilar. Las rutinas sobrecargadas se identifican por OID y este editor exige conservar la firma para no crear otra función accidentalmente. SQL Server: ALTER VIEW/PROCEDURE/FUNCTION con ANSI_NULLS/QUOTED_IDENTIFIER originales. Oracle: definición mediante DBMS_METADATA y CREATE OR REPLACE; se muestran errores de compilación si el motor guarda un objeto inválido. Se necesitan permisos de lectura y DDL de cada motor; módulos cifrados no son editables. SQLite: vistas dentro de SAVEPOINT en la copia local, con rollback si falla CREATE. ClickHouse: vistas SQL normales mediante CREATE OR REPLACE, sin edición de vistas materializadas desde este flujo. MongoDB: vistas con viewOn y pipeline mediante collMod; no hay procedimientos/funciones SQL almacenados.
- `npm run test:objects` valida el autocompletado de alias y su inserción, metadatos IPC, los tres tipos de objeto MySQL, revisión sin escrituras, aplicación explícita, copias, sesiones independientes y rechazo de sesión incorrecta en Electron. Las pruebas de modelo incluyen restauración ante error de CREATE, rollback de vista SQLite y restricciones de identidad/firma. Usan SQLite real en memoria y un simulador de protocolo MySQL, no servidores del usuario; el DDL de los otros motores necesita validación en sus versiones y permisos reales.

- Barras de herramientas compactas con separadores y tarjetas de ayuda al pasar el puntero o enfocar. En el editor: Pretty Formatter (Alt+Mayús+F), selección (Ctrl+Mayús+Enter), ejecutar todo (⚡ / F5) y relaciones. Modo oscuro está en la barra Workspace. El formateador trabaja sobre la selección o el documento y no ejecuta SQL. MongoDB usa formato JSON. Ctrl+Enter ejecuta la selección, si existe, o la sentencia del cursor; el botón de selección exige una selección.
- En Resultados: exportar CSV/XLSX, selector de 50/100/500/1.000 filas visibles y selector del resultado que se exporta cuando hay varios. El límite se aplica a la representación y exportación: no añade LIMIT/TOP/FETCH, no limita escrituras y no reduce por sí mismo el trabajo que realiza el servidor. Para limitar trabajo remoto usa la cláusula del motor en la consulta. Exporta los valores del resultado, con cabeceras, no el texto truncado visualmente de las celdas. CSV es UTF-8 con BOM y entrecomillado, protege cadenas que Excel podría interpretar como fórmulas. XLSX conserva esos valores como texto y avisa si una celda supera 32.767 caracteres; usa CSV para conservarla completa. Los NULL quedan vacíos.
- El diagrama de relaciones lee claves foráneas declaradas de SQLite, MySQL/MariaDB, PostgreSQL, SQL Server y Oracle. Permite elegir base/esquema visible, filtrar tablas con sus relaciones y usar zoom. Las flechas van desde la tabla que declara la FK hacia la referenciada; agrupa claves compuestas. La vista muestra hasta 80 tablas a la vez y pide filtrar si hay más. Los catálogos remotos de relaciones pueden quedar limitados a 1.000 columnas FK, con aviso. MongoDB/ClickHouse indican que no exponen relaciones compatibles; no se adivinan enlaces a partir de nombres. Leer el diagrama no cambia datos ni sustituye la consulta en el editor.
- Modo oscuro aplicado al editor, resultados, salidas, explorador y diálogos; recuerda la elección y la carga antes de pintar la interfaz. La preferencia de límite de filas también se conserva. `npm run test:query-tools` valida las barras, formateo, ejecución parcial, un diagrama FK real de SQLite, exportación y lectura de CSV/XLSX, ayuda flotante y persistencia del tema. Las exportaciones dependen de exceljs y el formateador de sql-formatter, con sus licencias correspondientes.

- Panel Salidas / Output debajo de los resultados, colapsado inicialmente. Registra hora, conexión, sentencia, éxito/error/aviso, filas devueltas/modificadas y duración. Conserva las últimas 200 ejecuciones durante la sesión; Limpiar vacía el historial. No almacena resultados ni historial de salidas en disco. La duración es la medida de ejecución disponible; no se inventa un tiempo Fetch separado.
- Arrastra la cabecera de Salidas para dejar el panel flotante o acoplarlo a un borde del área SQL (arriba, abajo, izquierda o derecha). La zona azul muestra dónde se acoplará. El selector de posición ofrece las mismas opciones con teclado. Escape cancela un arrastre. Los bordes del panel permiten redimensionarlo; en modo flotante usa la esquina inferior derecha. Los separadores admiten flechas, Mayús para pasos mayores e Inicio para restablecer tamaño. Posición, dimensiones y expansión se recuerdan localmente. El panel solo aparece en la vista SQL. `npm run test:outputs` verifica historial correcto/error, colapso, tamaño, cinco posiciones, arrastre real y persistencia.

- Logo LQTAC Data Base y espacio de trabajo en español.
- Paneles ajustables mediante separadores: ancho del lateral, altura de navegación frente al explorador y reparto de espacio entre SQL y resultados. Arrastra el divisor o enfócalo con Tab y usa las flechas (Mayús para pasos mayores). Doble clic restablece ese panel; Inicio/Fin llevan a sus límites. Los tamaños se guardan en este equipo y se adaptan al tamaño de la ventana sin ocultar completamente los paneles.
- Registro de módulos con su disponibilidad real.
- Conexiones en la barra de iconos izquierda. El espacio de trabajo está al pie del lateral, colapsado por defecto, y recuerda si el usuario lo abre. El explorador mantiene visibles todos los perfiles guardados: ⏻ verde indica una sesión abierta y ⏻ rojo una conexión cerrada; el botón conecta o desconecta ese perfil. Admite varias sesiones abiertas a la vez.
- Selección múltiple de conexiones con Ctrl/clic o Mayús/clic; botón derecho → Agrupar o Ctrl+Mayús+G. Arrastra las conexiones seleccionadas a un grupo, o a «Sin grupo» para sacarlas. El menú contextual incluye Conectar, Desconectar, Editar conexión, Borrar, Añadir a grupo y Agrupar. Los grupos y sus miembros se guardan localmente en `connection-groups.json`.
- Borrar elimina el perfil local y cierra solo sus sesiones; no elimina bases de datos. La configuración retirada se copia en `connections-trash.json`, sin contraseñas. Desagrupar conserva los perfiles. Las pestañas SQL quedan vinculadas a la conexión usada al crearlas y activan esa sesión al seleccionarlas; una consulta asociada a una sesión cerrada no se ejecuta contra otra conexión.
- Conexiones a servidor: todos los motores del selector (PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, ClickHouse y MongoDB) incluyen prueba, conexión, catálogo, consultas y desconexión. Se guardan en `connections.json`, sin contraseñas. Abrir archivos SQLite es una acción independiente.
- La contraseña se introduce al pulsar «Conectar», se usa en la sesión y no se guarda en disco. TLS es opcional y verifica el certificado del servidor mediante las autoridades de confianza del runtime; los certificados privados requieren una futura configuración de CA.
- Laboratorio SQLite con datos de proyectos y tareas.
- Apertura de archivos SQLite de hasta 100 MB como copia en memoria.
- Explorador jerárquico con contadores y filtro: MySQL/MariaDB, ClickHouse y MongoDB muestran bases; PostgreSQL, SQL Server y Oracle muestran esquemas de la base o servicio conectado. MongoDB muestra colecciones. La lista tiene desplazamiento propio y conserva carpetas abiertas.
- Pulsar una tabla o vista abre una consulta cualificada con la sintaxis del motor: LIMIT, TOP o FETCH FIRST. Las rutinas abren su definición (SHOW CREATE, pg_get_functiondef, OBJECT_DEFINITION o ALL_SOURCE). La estrella cambia la base o el esquema de resolución en PostgreSQL/Oracle; SQL Server usa consultas cualificadas y el esquema predeterminado del usuario, sin estrella. Oracle exige un servicio en el perfil; los demás admiten la base vacía con sus valores predeterminados.
- El botón ↻ actualiza el catálogo completo. Úsalo tras cambios de estructura o permisos: el catálogo remoto se conserva en memoria entre consultas para no recorrer todas las bases en cada ejecución.
- Editor con pestañas y borradores locales. El rayo separa el script antes de enviarlo al controlador; MySQL/MariaDB reciben una sentencia completa cada vez, sin activar múltiples sentencias en el driver.
- Ctrl+N para nueva consulta, Ctrl+Enter para ejecutar.
- Cada pestaña tiene un botón ×. Ctrl+W cierra la consulta activa; Ctrl+Mayús+T recupera la última cerrada, incluido su texto. Se conservan hasta 20 consultas cerradas para recuperación local. Cerrar la última vuelve a Inicio y mantiene la conexión abierta.
- Autocompletado local de tablas y vistas tras FROM, JOIN, UPDATE e INTO, o mediante Ctrl+Espacio. Usa el catálogo ya cargado, prioriza la base activa y admite `base.tabla`. Flechas para elegir, Enter para insertar, Escape para descartar. No ejecuta consultas al escribir ni sugiere dentro de comentarios o cadenas entre comillas simples. Actualiza el explorador para incorporar tablas nuevas.
- Resaltado SQL por colores en consultas, cuerpos de triggers, DDL y vistas previas: palabras clave, identificadores, cadenas, números, funciones, tipos y comentarios. Conserva el texto original, selección, cursor y autocompletado; el color es decorativo y no valida SQL. En alto contraste se usa el texto nativo y los scripts de más de 250.000 caracteres se muestran sin tokenizar para evitar bloquear la interfaz.
- Resultados reales, errores SQL y límite de visualización de 1.000 filas por resultado.
- Cuadrícula compacta con encabezados de una sola línea y desplazamiento horizontal para consultas con muchas columnas. Los valores largos se recortan visualmente y pueden consultarse completos al pasar el cursor; «Ajustar texto» permite mostrarlos en varias líneas sin partir los encabezados.
- Exportación mediante «Guardar copia» y aviso antes de cambiar de base.
- Editor de estructura MySQL/MariaDB: pulsa ✎ junto a una tabla; usa ＋ en la carpeta Tablas para preparar una tabla nueva. Se abre una pestaña independiente, con cambios pendientes hasta revisión y aplicación explícita.
- Columnas: añadir, renombrar, reordenar o eliminar; tipos y longitudes, PK, NN, UQ, B, UN, ZF, AI, columnas generadas VIRTUAL/STORED, DEFAULT literal o SQL, ON UPDATE CURRENT_TIMESTAMP, charset, collation y comentarios.
- Índices: clave primaria, normales, únicos, FULLTEXT y SPATIAL; simples o compuestos, prefijos, orden ASC/DESC, método, comentario y visibilidad cuando el servidor lo soporte. Claves foráneas: columnas locales/referenciadas y acciones ON DELETE / ON UPDATE. Las funciones específicas de versión siguen sujetas a la compatibilidad del servidor.
- Propiedades de tabla: nombre, motor, charset/collation predeterminados y comentario. DDL completo visible y abrible en el editor SQL. Particiones, permisos, índices funcionales y atributos avanzados sin editor específico se conservan y requieren SQL manual para modificarlos. El editor de estructura no está implementado para SQLite.
- Triggers: en la pestaña Triggers, «Crear trigger» o «Editar trigger» abre un editor de nombre, BEFORE/AFTER, INSERT/UPDATE/DELETE y cuerpo SQL (incluidos bloques BEGIN/END, sin DELIMITER). Se revisa el SQL antes de aplicar. Los cambios usan una conexión independiente con el modo SQL y la collation de creación, conservan el definer y el orden relativo si no cambia el evento. Si hay cambios pendientes de tabla, hay que aplicarlos o recargarlos primero.

MySQL requiere DROP + CREATE para modificar un trigger: existe un intervalo sin trigger y la operación no es atómica. Antes del DROP se guarda un JSON con la definición y el SQL de restauración en `trigger-backups` dentro del directorio de datos de la aplicación. Si falla CREATE y la conexión sigue operativa se intenta restaurar el original; ante pérdida de conexión se informa del resultado incierto, sin sobrescribir a ciegas. No se elimina un trigger si no se pueden confirmar permisos para recrear su definer original. Se comprueba la versión de la definición antes de aplicar, sin imponer un bloqueo exclusivo sobre el esquema.

El editor de estructura genera un CREATE TABLE o un único ALTER TABLE, muestra el SQL y los cambios destructivos y solo lo ejecuta al pulsar «Aplicar en servidor». Las operaciones DDL pueden bloquear o reconstruir la tabla, requieren permisos de servidor y no se revierten automáticamente. Antes de revisar y aplicar se comprueba que la definición y el modo SQL de la sesión siguen siendo los que se cargaron; las inserciones concurrentes que solo cambien el contador AUTO_INCREMENT no invalidan la revisión. La revisión caduca tras diez minutos y queda vinculada a la sesión activa. Es una comprobación optimista, no un bloqueo exclusivo del esquema.

En SQLite los archivos originales no se actualizan automáticamente: los cambios viven en memoria hasta exportarlos. Su ejecución es síncrona y una consulta costosa puede bloquear la ventana. No abrir archivos activos con cambios pendientes en WAL; utilizar una copia coherente de SQLite.

MySQL/MariaDB trabajan directamente contra la base real, con autocommit por defecto y transacciones explícitas mediante SQL. Seleccionar otra conexión mantiene la sesión anterior abierta; desconectar o borrar un perfil descarta las transacciones no confirmadas de esa sesión. Las consultas de la interfaz se ejecutan de una en una aunque existan varias conexiones abiertas. La conexión tiene un límite de 10 segundos; el tiempo máximo de las consultas se configura en ⚙ Configuración (30 segundos inicialmente). Agotar el tiempo de una operación de escritura no garantiza que el servidor la haya revertido: comprueba el estado antes de repetirla. El selector Filas permite 50, 100, 500, 1000 o Sin límite; los límites de tamaño y tiempo siguen aplicándose. Los borradores SQL se guardan en almacenamiento local sin cifrar: no incluir contraseñas.

## Límites entre módulos

`src/renderer/modules.js` registra las herramientas. El renderer gestiona presentación y borradores; `preload.cjs` expone operaciones concretas; `main.cjs` controla archivos y conexiones. Los adaptadores implementan consultas, metadatos y cierre; `renderer/dialect.js` centraliza comillas y consultas iniciales. Solo SQLite admite exportación. La interfaz no tiene acceso directo a Node ni a drivers.

Para JDBC se necesita un servicio Java/OSGi que aloje los bundles de modelo DBeaver y exponga conexión, esquema, consulta, cancelación y transacciones. No basta con importar los bundles en Electron. Diagrama ER, otros motores y empaquetado de instaladores quedan pendientes.

Pruebas: `npm test` valida perfiles, SQLite, consultas cualificadas y el protocolo MySQL con un servidor simulado local. `npm run test:desktop` valida credenciales, prueba/conexión, consultas MySQL, tres bases de datos, categorías, filtro, selección predeterminada, desplazamiento con 1.101 tablas y regreso al laboratorio SQLite. No contactan servidores del usuario ni acreditan compatibilidad con todas las versiones o configuraciones de autenticación de MySQL/MariaDB.

Dependencias exactas en `package-lock.json`. La distribución final debe incorporar avisos de DBeaver, Electron, SQLite, sql.js, mysql2, pg, tedious, oracledb, @clickhouse/client y mongodb, además del branding propio. El override de @azure/identity mantiene una versión compatible con Tedious que no arrastra MSAL 6 vulnerable; uuid se actualiza a 11.1.1, compatible con la API v4 usada por MSAL. La autenticación Azure no está expuesta por esta aplicación.

`npm run test:layout` verifica los tres separadores con arrastre real, persistencia tras recarga, límites de teclado, restablecimiento y ventanas pequeñas.

`npm run test:designer` comprueba inspección, alta de columna, revisión sin ejecución, aplicación explícita única, recarga, vista previa de índices y tablas nuevas y rechazo de una estructura cambiada por otra sesión. Utiliza un servidor de protocolo simulado; no modifica servidores reales ni sustituye pruebas de compatibilidad de DDL en cada versión de MySQL/MariaDB.

`npm run test:connections` valida la reorganización del lateral, estados apagados/encendidos, selección múltiple y agrupación por atajo, menú contextual, arrastre hacia un grupo y fuera de él, borrado recuperable de perfiles de prueba, recarga persistente y dos sesiones independientes, incluida la protección frente a ejecutar SQL en la sesión equivocada.

`npm run test:syntax` verifica los colores y la conservación exacta del SQL, cursor/selección, alineación al desplazarse, cambio de pestañas, composición de texto, editor de triggers, tamaños de ventana y representación segura de cadenas que contienen HTML.

## ClickHouse y MongoDB

En Conexiones → Nueva conexión selecciona el motor. ClickHouse usa HTTP (8123) o HTTPS con TLS verificado (habitualmente 8443), sin protocolo en el campo Servidor. No usa el puerto nativo 9000. La base predeterminada es `default`; usuario habitual `default`. Admite una sentencia SQL por ejecución, resultados JSONCompact y cambio de base con la estrella. Si escribes FORMAT, utiliza JSONCompact. El límite visible lo determina Filas (incluye Sin límite), con 16 MB por respuesta; la ejecución no se revierte si la respuesta excede el límite. La edición visual de estructura sigue reservada a MySQL/MariaDB.

MongoDB usa TCP (27017), TLS opcional, `authSource` configurable (admin por defecto), usuario/contraseña o usuario vacío para un servidor sin autenticación. La base predeterminada es `test`. Esta primera integración admite host y puerto; las URI SRV de Atlas, réplicas configuradas por URI y autenticación X.509 quedan pendientes. El explorador muestra Colecciones y Vistas. El editor usa un comando JSON / Extended JSON, con colores y autocompletado de colecciones de la base seleccionada. No ejecuta JavaScript de mongosh. Ejemplos:

```json
{"find":"clientes","filter":{"activo":true},"limit":100}
```

```json
{"aggregate":"clientes","pipeline":[{"$match":{"activo":true}}],"cursor":{}}
```

El campo opcional `$db` selecciona la base para ese comando sin cambiar la predeterminada; los enlaces del explorador lo incluyen. Los comandos de escritura como insert, update, delete o create se ejecutan en el servidor al pulsar Ejecutar, con los permisos del usuario. Los cursores se consumen mediante el driver y se cierran incluso al alcanzar el límite de documentos seleccionado. Los valores BSON especiales se muestran en Extended JSON para conservar tipos. No se guardan contraseñas y no hay integración con modelos de lenguaje.

`npm test` incluye pruebas HTTP y de protocolo MongoDB con los drivers reales contra servidores locales simulados. `npm run test:engines` verifica además formularios, puertos, TLS, IPC, sesiones simultáneas, explorador y editor SQL/JSON en Electron. Estas pruebas no certifican todavía compatibilidad con un servidor ClickHouse/MongoDB real del usuario. Los estados encendidos representan sesiones lógicas abiertas; en HTTP/MongoDB una pérdida de red se detecta al realizar operaciones, sin sondeo periódico remoto.

## PostgreSQL, SQL Server y Oracle

Todos disponen de controladores de conexión, catálogos por esquema, consultas y resultados; los formularios no incluyen motores «pendientes». La edición visual de estructura y triggers sigue siendo específica de MySQL/MariaDB. Se pueden ejecutar sus instrucciones DDL manualmente en el editor SQL.

- PostgreSQL: puerto 5432, base `postgres` si queda vacía, usuario/contraseña, TLS opcional con certificado verificado. Catálogo y rutinas para PostgreSQL 11 o superior. La estrella usa SET search_path; para otra base del servidor crea otro perfil. Mantiene una sesión física, transacciones BEGIN/COMMIT/ROLLBACK y temporales. El plazo por sentencia es configurable; el límite del servidor se actualiza antes de ejecutar y se añade un plazo total de respuesta. Los errores de SQL no cierran una sesión sana; un error dentro de una transacción necesita ROLLBACK.
- SQL Server: puerto TCP 1433 o el puerto configurado de la instancia, autenticación SQL por usuario/contraseña, base predeterminada del login si queda vacía y TLS opcional verificado. No incluye autenticación Windows integrada, NTLM ni Azure. El host no debe incluir `\\instancia`: configura su puerto TCP. Ejecuta lotes T-SQL en una conexión persistente, conservando temporales y transacciones. GO es un separador de herramienta, no SQL del servidor: ejecuta cada lote por separado. USE cambia de base y actualiza el catálogo. El explorador genera SELECT TOP (100), las rutinas se leen con OBJECT_DEFINITION si hay permiso VIEW DEFINITION. El tiempo máximo por consulta se configura en ⚙ Configuración.
- Oracle: puerto 1521, campo Servicio Oracle obligatorio (por ejemplo FREEPDB1 o XEPDB1), autenticación usuario/contraseña y modo Thin para Oracle 12.1 o superior, sin Oracle Client. TLS activa TCPS con verificación de nombre del servidor; wallets, SID, descriptores TNS y Thick Mode no se configuran en esta interfaz. El explorador usa ALL_OBJECTS y cambia CURRENT_SCHEMA, sin cambiar de servicio. DML no confirma automáticamente: usa COMMIT o ROLLBACK; desconectar descarta cambios sin confirmar. DDL conserva la confirmación implícita de Oracle. Ejecuta una sentencia o bloque PL/SQL por petición: se retira el punto y coma final de SQL, se conserva el de PL/SQL y se elimina el separador `/` final en su propia línea. La consulta generada usa FETCH FIRST 100 ROWS ONLY. NUMBER se solicita como texto para conservar precisión. Los LOB se identifican con un marcador: usa SUBSTR/DBMS_LOB.SUBSTR o una conversión para consultar su contenido. callTimeout recibe el tiempo configurado para cada viaje de red; el ejecutor añade un plazo global para la sentencia y su lectura de resultados.

Estos adaptadores aplican el selector de filas (incluye Sin límite) y conservan un límite de 16 MB de datos retenidos por ejecución. Una escritura puede haber llegado al servidor aunque falle la respuesta: no se reintenta automáticamente. TLS privado requiere certificados de confianza configurados fuera de este formulario.

`npm test` incluye PostgreSQL contra un simulador de protocolo con el driver pg real, y SQL Server/Oracle contra dobles de las APIs de los controladores (incluyen errores, resultados, catálogo, cambios de esquema, transacciones Oracle y cierre de cursores). `npm run test:sql-engines` recorre prueba/conexión, formularios, consultas, resultados y tres sesiones simultáneas en Electron con esos mismos entornos de prueba. No se ha certificado aún una conexión real a SQL Server u Oracle ni sus distintas versiones y configuraciones de autenticación. Referencias de las APIs: [pg.Client](https://node-postgres.com/apis/client), [Tedious Connection](https://tediousjs.github.io/tedious/api-connection.html), [node-oracledb](https://node-oracledb.readthedocs.io/en/latest/user_guide/connection_handling.html).
